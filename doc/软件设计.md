# 智能家居 AI 开灯 —— 软件设计文档

## 1. 概述

本文档描述【智能家居 AI 开灯】产品的软件设计。产品通过 **ESP-12F 主控 + ASRPRO 离线语音模块**，实现在进门时自动开灯，以及语音开关灯。

本仓库只实现 **ESP-12F 固件**；ASRPRO 固件在另一个项目中实现，两者通过 UART 串口对接。第 6 节定义了二者之间的接口契约。

## 2. 需求

- 自动开灯：光照 < 100 lx **且** 超声波距离 < 20 cm（有人进门）时，舵机旋转 90° 拨动实体灯光开关再回正；两者不同时满足则不动作。
- 语音开灯：ASRPRO 识别“打开灯光”→ 经串口发给 ESP-12F → 舵机动作 → 结果回传 → ASRPRO 喇叭播报。
- 语音关灯：同上（“关闭灯光”）。

## 3. 系统架构

```
              UART (9600 8N1, 双向)
 ASRPRO  ◄──────────────────────────►  ESP-12F
 (离线语音)                                │
    ├ mic 输入                             ├── I2C ──────► GY-302 / BH1750  (光照)
    └ speaker 输出                         ├── TRIG/ECHO ► HC-SR04          (进门测距)
                                          └── PWM ──────► SG90 舵机        (拨实体开关)
```

职责划分：

- **ASRPRO**：语音唤醒/识别 + 播放提示音；把“开灯/关灯”命令按第 6 节协议编码后经 UART 发出，接收 ESP-12F 的执行结果并播报对应语音。
- **ESP-12F**：唯一决策者与执行者。采集光照与距离、维护灯的开关状态、驱动舵机、处理语音命令。

## 5. 引脚分配（ESP-12F）

| 信号 | GPIO | 丝印 | 说明 |
|---|---|---|---|
| BH1750 SDA | GPIO4 | D2 | 数据 |
| BH1750 SCL | GPIO5 | D1 | 时钟 |
| HC-SR04 TRIG | GPIO13 | D7 | 触发（输出） |
| HC-SR04 ECHO | GPIO12 | D6 | 回波（输入，3.3V 供电直连） |
| SG90 信号 | GPIO14 | D5 | PWM |
| ASRPRO UART | GPIO1 / GPIO3 | TX / RX | 语音通信（9600） |

供电注意事项：

- SG90 建议 5V 单独供电并与 ESP-12F 共地；仅 3.3V 供电力矩不足。
- HC-SR04 采用 3.3V 供电（与 ESP-12F 同源）；ECHO 输出约 3.3V，直连 GPIO12，无需分压。注意：HC-SR04 标称 5V，3.3V 下发射强度降低、有效测距缩短，且可能偶发假回波，固件以 `DIST_MIN_VALID_CM` 过滤盲区假值。
- BH1750 的 ADDR 引脚决定 I2C 地址（0x23 或 0x5C），固件自动探测，无需接线调整。

## 6. UART 通信协议（与 ASRPRO 项目的接口契约）

物理层：UART 9600 8N1。文本帧，每帧以换行结尾（兼容 `\n` 与 `\r\n`）。

ASRPRO → ESP-12F（指令）：

| 帧 | 含义 |
|---|---|
| `ON\n` | 打开灯光 |
| `OFF\n` | 关闭灯光 |

ESP-12F → ASRPRO（响应）：

| 帧 | 含义 | 建议播报语 |
|---|---|---|
| `ON_OK\n` | 已执行开灯 | “已打开灯光” |
| `OFF_OK\n` | 已执行关灯 | “已关闭灯光” |
| `ON_SKIP\n` | 灯已是开（未动作） | “灯光已开” |
| `OFF_SKIP\n` | 灯已是关（未动作） | “灯光已关” |
| `ERROR\n` | 执行出错 | “操作失败” |

约定：ASRPRO 仅在主动发送指令后才等待一条对应响应；自动感应开灯不回传（此时 ASRPRO 未在等待）。

## 7. 控制逻辑 / 状态机

状态：`lightState ∈ { Off, On }`，表示实体灯开关当前的逻辑状态。

- **初始状态**：上电用 BH1750 采样数次取平均，亮度 ≥ 100 lx 判为 `On`，否则 `Off`（近似值；可扩展 EEPROM 掉电记忆）。
- **自动开灯**（每 100 ms 采样）：
  - 计算 `near = (0 ≤ dist < 20 cm)`，取其上升沿（由无人变有人）；
  - 当「near 上升沿 **且** lux < 100 **且** state == Off」→ 舵机拨开关 → `state = On`。
- **语音命令**（即时响应）：
  - 开灯：`state == On` → 回 `ON_SKIP`；否则拨开关 → `state = On` → 回 `ON_OK`。
  - 关灯：`state == Off` → 回 `OFF_SKIP`；否则拨开关 → `state = Off` → 回 `OFF_OK`。

关键点：因为实体开关是 toggle 型，开灯与关灯共用同一机械动作，固件必须用 `lightState` 记录状态，仅当状态真正变化时才拨动，避免重复拨动造成状态反转。

## 8. 关键设计决策与边界情况

- **toggle 语义**：开灯 / 关灯都是「舵机转 90°→回正」同一个动作；方向（顺时针/逆时针）由机械安装方向决定，可在 `config.h` 中调整 `SERVO_ANGLE_*`。
- **幂等**：语音“开灯”在灯已开时不再动作（回 `ON_SKIP`），避免把灯又拨回关闭。
- **自动与语音一致性**：统一由 `lightState` 保证，两条路径不会互相打架。
- **阻塞时长**：舵机一次动作约阻塞 750 ms（450 ms 停留 + 300 ms 回位），期间不处理串口；ASRPRO 会延迟约 750 ms 收到响应（播报前延迟在可接受范围内）。

## 9. 与 ASRPRO 项目的边界

- 本仓库：ESP-12F 固件（PlatformIO + Arduino）。
- 另一个项目：ASRPRO 固件（天问Block / 天问IDE），负责识别 → 发 `ON`/`OFF` → 收响应并播报。
- 二者唯一耦合点是第 6 节 UART 协议。改动协议必须两边同步。

## 10. 构建与调试（本仓库）

- 依赖：VS Code + PlatformIO，配置见 [platformio.ini](../platformio.ini)。
- 构建 `pio run`；烧录 `pio run -t upload`；串口监视 `pio device monitor`。
- 调试日志由 [config.h](../src/config.h) 的 `DEBUG_LOG` 开关控制；启用时日志输出到 UART0（与 ASRPRO 共用），开发期可先拔掉 ASRPRO、用 USB-TTL 观察，量产前保持关闭。
